# Project Rules

## Teaching
- Use plain English. Explain every technical word in one sentence the first time you use it, and add it to `docs/GLOSSARY.md`.
- Before each phase: say WHAT you will do and WHY, in at most 5 sentences.
- After each phase: give me a summary with 4 parts: (1) what changed, (2) why professionals do it this way, (3) how I can check it works (what to click or see), (4) one thing I should now understand.
- Do ONE phase at a time. When it ends, STOP and wait until I say "go to the next phase".

## Safety
- Do not change how the Home page or Dashboard look or behave. This round is about structure only.
- Never delete code. Unused code goes to `frontend/src/_parked/` with a comment explaining what it was.
- Never print or hardcode secret keys. If you find one, tell me the file name only, not the value.
- Use clear file names. One job per file. Keep files under about 200 lines.
- Start every file with a short comment: what it does, who uses it, what it talks to.
- Before each phase, remind me to save a git commit (a saved snapshot I can return to) and give me the exact commit message.

## Loop protection
- Do not re-read or re-do work from finished phases.
- If something fails twice, STOP, explain the problem in plain words, and ask me. Do not keep retrying or rewriting.
- Do not add features or tools I did not ask for.
